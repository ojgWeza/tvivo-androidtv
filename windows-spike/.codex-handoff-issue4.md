# Issue 4 handoff — rewind and forward controls

## Implemented

- Added shared `PlaybackTimeline.ClampSeekTarget`, which bounds seeks to `0..DurationMilliseconds` and rejects duration-bounded seeks when duration is unknown (`src/Tvivo.Core/Contracts.cs`).
- Added app-owned 10-second rewind and forward buttons. Both buttons and the progress slider are enabled only for a known-duration active/paused/buffering/ended session. All seek paths use the same clamping helper and call the selected engine directly; none starts or restarts playback (`src/Tvivo.App/MainWindow.xaml`, `src/Tvivo.App/MainWindow.xaml.cs`).
- Both engines clamp their own `Seek` calls against their current `PlaybackTimeline` (`src/Tvivo.Playback/WindowsPlaybackEngine.cs`, `src/Tvivo.Playback/FFmpegInteropPlaybackEngine.cs`).
- The app-owned transport is now shared by native and LibVLC playback; WinUI's native transport controls are disabled to avoid duplicate controls. Cinema mode continues to hide the transport.

## Deviations and uncertainty

No functional scope deviation. Making the controls consistent across both engines required using the app-owned transport for native playback too. Source-level diff/whitespace review only; no build, run, launch, or tests were performed. Button layout and engine seek behavior remain runtime-unverified.
