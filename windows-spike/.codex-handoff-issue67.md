# Issue 6/7 handoff — catalog ordering

## Implemented

- `src/Tvivo.Infrastructure/SqliteCatalogRepository.cs` now exposes separate ordered queries for Recently Added, Favorites, and Continue Watching.
- Recently Added sorts by the provider's `added_at` value descending, then `id` ascending for stable ties. `added_at` is populated from Xtream's `added` field; zero/missing dates are excluded from this shelf.
- Continue Watching sorts by `resume_updated_at DESC`, then `id ASC` for stable ties. Its timestamp remains independent from both catalog and favorite dates.
- Favorites sort by `favourite_added_at DESC`, then `id ASC`. `SetFavorite` sets the favorite timestamp on the transition to favorite and clears it on removal. `UpdateResumePosition` records position and its own update timestamp.
- The cache schema advances from v9 to v10. New databases create `favourite_added_at` and its ordering index. Existing v9 databases add the nullable timestamp and index in a transaction. Existing v8 databases still run the title-cleanup migration first, then advance through v9 to v10.

## Migration implication

Existing favorite flags and resume positions are preserved by the additive migration. Historical favorite-add times cannot be reconstructed because v9 had no such field; those rows have a null `favourite_added_at` and use the stable ID tie-break until the user removes and adds them again. The migration does not alter `added_at`, `resume_updated_at`, or the existing snapshot behavior.
