# Round 4 investigation and implementation plan

Scope: items 2, 5–9. Code inspection only; no build, test, provider request, or timing measurement. Paths below are relative to `windows-spike/`. The account's actual provider payload is unavailable, so provider-specific absence of file sizes remains unverified.

## 2. Spotlight click to player

**Cause.** `CatalogLandingPage.xaml.cs:3011-3035` raises selection after materializing eight related channels. `RaiseChannelSelected` calls `CaptureBrowseState` synchronously (`:5396-5402`). For movies with no `DirectUri`, `MainWindow.xaml.cs:1805-1814` awaits `ResolvePlayableChannelAsync` before `ShowPage(Player)` at `:1860`; that resolver performs a SQLite `GetChannel` on a worker (`CatalogLandingPage.xaml.cs:270-278`). Shelf cards use the same selection handler (`:4656-4674`), so the difference requires timings; it is not proven Spotlight-specific. Loading artwork is assigned later in `StartPlaybackAsync` (`MainWindow.xaml.cs:3059-3070`). No engine cold-start conclusion is supported yet.

**Slice A (design care).** In `MainWindow.xaml.cs`, immediately set selected title, cover, loading curtain/bar and `ShowPage(Player)` on movie selection; then resolve the URL asynchronously with a generation/cancellation guard, showing a retry state on failure. Keep `StartPlaybackAsync` after successful resolution. Add redacted `perf.selection` click-to-player-visible and resolve timings, from both Spotlight and shelf, using the first rendered frame rather than the `ShowPage` call as the visible endpoint. Avoid names, IDs, and URLs in diagnostics. Pure Core: `PlayerSelectionTransitionPolicy` for stale-result/error handling; xUnit race and failure tests. **Slice B (mechanical after A):** On `OpenSpotlight` hover/keyboard open, pre-resolve only metadata/URL objects, bounded to the current open card; cancel on close/account change. Never open a stream. Before/after is currently **unmeasured**; expected gain is the URL lookup duration plus any startup work moved past first paint.

## 5. File size

**Direct answer.** It should appear in the hover/Spotlight details line (`CatalogLandingPage.xaml:127,466`, `.xaml.cs:5786-5794`), episode list (`MainWindow.xaml:825-826`), and player metadata line (`MainWindow.xaml.cs:3663-3687`). It is hidden when size is null. The code parses only `size`, `filesize`, `file_size`, or `size_bytes` in list/detail JSON (`XtreamInfrastructure.cs:337-342,439-460`) and episode `info` (`:297-323`). `movie_data.container_extension` is a format, not a size; bitrate/duration do not provide a reliable file byte count. `GetMetadata` treats a previously fetched row with null size as complete (`SqliteCatalogRepository.cs:170-181`), so `LoadPlayerMetadataAsync` skips another provider fetch (`MainWindow.xaml.cs:3610-3618`). Whether **her** provider omits size is not determinable without redacted payload-field diagnostics. Existing DB wiring preserves size on refresh (`SqliteCatalogRepository.cs:333-337`).

**Slice A (mechanical):** Add a `FileSizeAvailabilityPolicy` pure Core unit distinguishing unknown from known bytes; show a labeled `File size: …` consistently on hover, Spotlight open card, movie/player detail, and episode rows. Update metadata lookup to refresh a null-size result at a bounded interval, without repeated provider requests. Log `perf.file-size` source/present flags only. Test formatter, null/known states, parser shapes, and cache expiry. **Slice B (design/network care, only if diagnostics confirm no provider size):** Settings toggle **off by default**, “Show file sizes (checks the provider)”. Probe one open Spotlight card or opened details item via HEAD, then `Range: bytes=0-0` only if needed; accept valid total length, cancel when playback starts, max one request, never lists, persist bytes in SQLite, redact diagnostics. MockWebServer tests for headers, unsupported responses, concurrency, cancellation; no stream playback tests. Risk: a misbehaving provider may send a full response to Range; abort after headers and do not read a body.

## 6. Home opens below Spotlight

**Direct answer.** The code restores the previous For You position, not an intentional jump to Continue Watching. Home and My Tvivo buttons both call `ShowCatalogAsync(MyTvivo)` (`MainWindow.xaml.cs:1014-1018`). Mode exit captures its scroll position (`CatalogLandingPage.xaml.cs:865-868`), and snapshot apply restores a saved first shelf or offset (`:2729-2742`, `:3452-3525`). Continue Watching being the first shelf simply makes it the visible landing point.

**Slice (mechanical):** Pass a navigation intent from `HomeNavigation_Click` through `ShowCatalogAsync`/`PrepareModeAsync`. For explicit Home entry, discard the MyTvivo browse position and reset the shared scroller after apply/layout; retain restoration for player Back. Add pure Core `CatalogScrollEntryPolicy` tests for Home, tab switch, Back, and refresh. Risk: delayed restore callback can undo reset; invalidate `_browseRestoreGeneration` on explicit Home.

## 7. Spotlight settings

**Cause.** Both Movies and Series controls exist (`AccountPage.xaml:92-164`), but sit in a long page-level `StackPanel` with no outer scroll (`:5-6,63-182`). Only the inner folder lists scroll (`:118-121,155-158`); at narrow size/high scale the Series section and Save/Cancel can be beyond the viewport. Folder sources are read synchronously from `GetCategoryShelfDescriptors` (`AccountPage.xaml.cs:323-333`), whose SQL excludes empty folders with `HAVING COUNT(i.id)>0` (`SqliteCatalogRepository.cs:377-405`); before item refresh, the list can be empty. Chosen-folder panels are also collapsed unless the matching selector is in `SpecificFolders` mode (`AccountPage.xaml.cs:335-350`). Save/Cancel already have separate draft behavior (`:295-329`). There is currently one Movies setting and one Series setting shared by page types, not separate per-page choices.

**Slice A (design care):** Replace the page root with a bounded, keyboard/touch/wheel-scrollable layout. Offer three clearly named page groups: Movies (movie source), Series (series source), and For You (movie and series sources, 4+4). Each source is “Recently added” or “Chosen folders” with the matching provider folder checklist. Give lists bounded height, explicit empty/loading messages, search only when count >15, wrapped labels, >=16 DIP type, >=44 DIP targets, automation names, and reachable Save/Cancel at 100–200% scale. Preserve old `UnexploredFolders` selections in a compatible legacy path until a migration is defined. **Slice B (mechanical):** Load movie/series categories asynchronously without requiring nonzero item counts; distinguish “catalog still loading” from “no provider folders”. Extend `SpotlightSettings`/`SpotlightSettingsStore` with optional per-page source settings: existing Movies/Series values seed both their own pages and For You on old records. Update `SpotlightSettingsService` page selection, preserve folder IDs, and keep Save/Cancel atomic. Pure Core `SpotlightFolderSelectionPolicy` tests for type separation, unavailable IDs, search threshold, legacy deserialization, and Save/Cancel. Risk: old records must retain the same selection until the user explicitly saves new page-specific choices.

## 8. Series artwork

**Cause.** `XtreamInfrastructure.cs:345-361` accepts only absolute HTTP(S) cover/backdrop paths. A relative `cover` therefore maps to null (`:439-460`), and `ReplaceSnapshot` writes null artwork (`SqliteCatalogRepository.cs:333-337`). Existing cached rows need a non-destructive refresh after parser correction. Independently, `ToEpisodeChannel` explicitly assigns null `LogoUri` (`MainWindow.xaml.cs:2206-2223`), causing `StartPlaybackAsync` to show popcorn (`:3059-3068`), even if the series has a cover.

**Slice A (design care):** Resolve safe relative cover/backdrop paths against the provider base URI in `ArtworkUri` without allowing unsafe schemes; refresh Series snapshot on parser-version bump, preserving favorites/progress. Ensure series card/search/hover/header all consume stored `LogoUri`. **Slice B (mechanical):** Carry the parent series `LogoUri` through `ToEpisodeChannel` to rows and player loading. Pure Core `SeriesArtworkPolicy` tests for absolute, relative, empty, array fallback and episode inheritance; Infrastructure JSON-to-`ReplaceSnapshot`/readback test with realistic shapes. Risk: provider-relative URL conventions vary; verify against redacted field-shape diagnostics, never log URLs.

## 9. Tab-switch caching

**Cause.** A snapshot cache already exists (8 entries/64 MiB; `CatalogLandingPage.xaml.cs:106-108,125-126,3325-3350`), but validity checks only Spotlight settings revision (`:3318-3319`), and inactive previews are stripped (`:3351-3371`). Each mode switch may hold the old page then show loading after 300 ms (`:896-932`); `LoadCatalogAsync` can delay 32 ms (`:1225-1233`), and `ApplySnapshotAsync` can fade and rebuild UI (`:2649-2655,2695-2721`). Return is therefore not guaranteed instant. Existing cache does not represent a retained rendered shelf view or full catalog revision.

**Slice A (design care):** Add a per-account/per-mode **rendered page** cache for last three pages, keyed by full catalog + Spotlight/activity/favorite revision. Show cached visual models on tab entry before async revalidation; apply only a changed revision. Preserve per-page scroll, release on account switch/sign-out/memory pressure, and retain only visible artwork. Pure Core `CatalogPageCachePolicy` tests for three-page LRU, account isolation, revision invalidation, and stale async completion. **Slice B (mechanical):** Add redacted `perf.page-switch` click-to-first-paint, cache hit/miss, DB read, render, artwork timing for For You→Movies→For You→Series→Movies. No measured baseline exists; expected gain on a warm return is removal of DB/build/fade time, bounded by UI reattachment and first-frame scheduling.

Verification for implementation: focused Core and Infrastructure tests (exclude `Dpapi` and `Credential`), then a permitted build. A live look alone can verify actual provider field availability, layout at 100–200% scale, artwork on her account, and perceived first-paint timings. No stream should be opened by automated tests.
