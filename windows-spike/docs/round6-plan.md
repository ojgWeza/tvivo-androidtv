# Round 6: root cause and recommended implementation plan

Scope: planning only. Paths below are relative to `windows-spike/`. No source edits or runtime checks are part of this round. Keep technical copy in English. Audience constraints throughout: text at least 16 DIP (18 DIP for transient player messages), strong contrast in both themes, interactive targets at least 44 × 44 DIP, no flashing, and reduced-motion support. No automated test may open a provider stream.

## Recommended order and ownership

1. **A1 (Sol medium):** repair exact-size scheduling, persistence, and redacted diagnostics. This is the user-visible defect and a data correctness issue.
2. **A2 (Sol medium):** add defensible estimates and DB presentation after exact probing is reliable.
3. **B (Luna medium):** move transient loading text into the curtain below the bar; verify both themes visually.
4. **E (Sol medium):** simplify the timer policy and all full/compact presentations together.

A single owner-approved manual player/emulator run after the implementation batch should cover stream-dependent behavior; development approval alone does not authorize deployment or emulator testing.

## A. File size: exact first, estimate second

### Root cause supported by code

The measured provider responses have no size, while the media endpoint exposes an exact byte total through HEAD `Content-Length` and ranged GET `Content-Range`. The current parser maps missing size to `null` (`src/Tvivo.Infrastructure/XtreamInfrastructure.cs:232-244,337-348`). `SqliteCatalogRepository.SaveMetadata` nevertheless writes `size_checked_at=UtcNow` for **every** metadata save, including a size-free response (`src/Tvivo.Infrastructure/SqliteCatalogRepository.cs:209-220`). `LoadPlayerMetadataAsync` requests that response on movie open and saves it (`src/Tvivo.App/MainWindow.xaml.cs:3714-3734`). Later `ProbeCurrentFileSizeAsync` reads this stamped absence and `ShouldProbe` applies the seven-day `ShouldCheck` gate (`src/Tvivo.App/MainWindow.xaml.cs:3808-3823`; `src/Tvivo.Core/FileSizeAvailabilityPolicy.cs:10-34`). This is a direct explanation for movie-details coverage logs with no `filesize.probe` log: the latter is emitted only inside `HttpFileSizeProbe.ProbeAsync` (`src/Tvivo.Infrastructure/HttpFileSizeProbe.cs:75-82`). The call is skipped before that point.

There are further silent paths. Probe scheduling occurs only after `FirstFrame` (`src/Tvivo.App/MainWindow.xaml.cs:3428-3453`), and the `Task.Run` worker then reads `_engine.IsPlaying` (`:3794-3807`); paused/buffering/stopped states can leave it waiting, while a thread-affinity exception would be swallowed without logging. The scheduler exits without diagnostics for missing channel, direct URI, or account (`:3779-3786`). `_fileSizeProbedThisSession.Add(key)` occurs **before** the policy gate (`:3788-3794`), so reopening the same title in the same process cannot retry a skipped or failed probe. Cancellation disposes the source while the worker still accesses `cancellation.Token` (`:3797-3824,3861-3866`), and the outer `catch` suppresses all exceptions (`:3850-3853`). An older executable remains possible, but code inspection cannot establish that; log the app/build version at startup to distinguish it. A generation mismatch can discard a result after probing, but it cannot explain the total absence of `filesize.probe` once the HTTP probe actually starts.

### Exact-size design

* Separate **provider metadata fetch time** from **media probe time**. `SaveMetadata` must preserve `size_checked_at` when no size was supplied; never mark a metadata response as a media-size check. Preserve a prior exact `size_bytes` against null metadata or null probe results. Add a one-time migration/data repair that clears legacy `size_checked_at` where `size_bytes IS NULL`; even without it, open-item policy ignores a stored absence. Keep the seven-day interval only for optional background/list lookups; do not issue bulk media probes from cards.
* Introduce `FileSizeProbePolicy.ShouldProbeOnOpen(kind, exactBytes)` (movie/episode and no real exact bytes). An opened item always qualifies, regardless of `size_checked_at` or any estimate. Use a per-item **in-flight** guard, released on completion/cancellation, rather than a process-lifetime tried set. Recovery/retry of the same playback generation does not start another request; a later deliberate open may retry. If exact bytes are already stored, show them immediately and skip network.
* Make probe ordering explicit in the movie, episode, and related-item entry paths (`src/Tvivo.App/MainWindow.xaml.cs:1956-1966,2324-2376,5381-5432`). The account's observed `max_connections` can be one. **Do not probe concurrently with a media request or active old stream.** After URI resolution and after any old engine is stopped, perform a short pre-playback **HEAD first**; measured HEAD supplies the exact total without a body. If HEAD fails, lacks a plausible length, or is unsupported, issue one `Range: bytes=0-0` GET with `ResponseHeadersRead`, validate a `206` total (or a valid full `200` length), and immediately dispose the response without reading a body. Cap the complete preflight to about two seconds, cancel on navigation, then start playback regardless of outcome. This trades at most a short first-frame delay for no second active connection. If stop-before-probe cannot be guaranteed on a transition, defer the probe to the next open instead of overlapping streams. Live remains excluded.
* Preserve the existing 1 MB–200 GB plausibility bounds and decimal GB display (`src/Tvivo.Core/FileSizeAvailabilityPolicy.cs:27-58`; `src/Tvivo.Core/FileSizeFormatter.cs:26-40`). Validate status and headers together: HEAD `200` plus non-chunked `Content-Length`; ranged GET `206` plus `bytes 0-0/TOTAL`. A `200` ranged response may use full `Content-Length` only when the body is demonstrably the whole file. Reject zero, unknown totals, partial-length-as-total, overflow, and conflicting headers. A failed probe leaves any existing exact size intact. The callback must reload/retain movie metadata instead of passing `_currentSeriesMetadata` (null for movies) to `SetPlayerMetadata`, which currently drops year/rating/genre after a size update (`src/Tvivo.App/MainWindow.xaml.cs:3831-3848,3869-3896`).
* Add a redacted orchestration result for **every open decision**, including skipped paths: `event=filesize.probe result=found|none|failed|skipped reasonCategory=exact_cached|head_length|range_total|no_uri|no_account|unsupported_kind|cancelled|timeout|http_status|invalid_header|network|stale_generation|storage_error ms=N`. HTTP and orchestration should share one attempt ID made of an opaque counter, not account/item/URI. Never log a media URI, provider identity, credential, raw response header, or item title. Log startup build version separately. The current HTTP-only log (`src/Tvivo.Infrastructure/HttpFileSizeProbe.cs:75-82`) cannot prove scheduling or policy decisions.

### Estimate fallback

Store exact bytes only in existing `size_bytes`. Add nullable `estimated_size_bytes` (and optionally a small source enum) to both `items` and episode `media_progress` in the next SQLite schema migration (`src/Tvivo.Infrastructure/SqliteCatalogRepository.cs:145-185,209-251`). Render `size_bytes` first; otherwise render `~` plus formatted estimate, for example `File size: ~1.4 GB`. A later exact probe atomically wins without deleting an estimate; a failed probe must not overwrite either. Read the estimate into `CatalogMetadata`/episode channels (`src/Tvivo.Core/Contracts.cs:86-92`; repository `GetChannel`/`GetChannels` at `:531-579`) so the player metadata line, current playlist row, and catalog cards/hover can display it from DB with **no media-network call on hover** (`src/Tvivo.App/MainWindow.xaml.cs:3869-3896,6462-6479`; `src/Tvivo.Infrastructure/HoverMetadataLookup.cs:68-92`). Mark approximation in visible text and automation name.

Estimate only from a **total** bitrate plus credible duration: `round(totalKbps × 1000 × durationSeconds / 8)` bytes, using checked arithmetic. For movies, read `info.bitrate` and parse `info.duration` (numeric seconds or `hh:mm:ss`); use `info.duration_secs` only if duration is absent and its value passes validation against a known playback timeline. For episodes, read `ep.info.bitrate` and `ep.info.duration` first, then episode-level `duration`; current `MapEpisodes` only reads episode-level duration (`src/Tvivo.Infrastructure/XtreamInfrastructure.cs:302-327`). Do not trust this provider's `duration_secs` when `duration` disagrees. If total bitrate is absent, use a clearly documented sum of parsed video and audio bitrates only when both units and streams are unambiguous; otherwise show no estimate. Accept, for example, 128–80,000 kbit/s, 60 seconds–8 hours, and a resulting 1 MB–200 GB; reject zero, malformed units, overflow, and implausible combinations. Container extension alone cannot justify a numerical size: compression and content vary too much. An estimate is lower confidence than an exact header and must never suppress an open probe.

**Tests:** `tests/Tvivo.Core.Tests/DisplayPoliciesTests.cs` for open-versus-background seven-day behavior, exact-over-estimate formatting and duration/bitrate plausibility; `tests/Tvivo.Infrastructure.Tests/HttpFileSizeProbeTests.cs` with fake handlers for HEAD success, HEAD→206 fallback, range ignored, chunked/invalid totals, timeout/cancel, disposal; `tests/Tvivo.Infrastructure.Tests/SqliteCatalogRepositoryTests.cs` for legacy timestamp repair, null preservation, estimate/exact precedence and episode persistence; `tests/Tvivo.Infrastructure.Tests/HoverMetadataLookupTests.cs` for DB-only estimated display. One owner-approved manual movie and episode check should confirm a probe decision line, an HTTP result line, and exact size in player and reopened card; no automated stream opening. **Risks:** transient probe delay, provider counting HEAD as a connection until disposal, an old stream still active during an in-player switch, and racing metadata saves. Make stop/probe/play ownership and SQL update precedence explicit before release.

Give it the same curtain-local white brush as `PlayerLoadingText`, at least 18 DIP, centered, wrapping, and polite live-region updates only when wording changes. Do not use the theme-dependent `PlayerTitleText` brush directly on a black curtain, since it may be dark in light theme (`MainWindow.xaml:572`). Keep both loading title and status the same white curtain brush in light and dark themes.

## C. Movie/series category browser inside the player

Today the sidebar binds one `ObservableCollection<PlayerListEntry>` (`src/Tvivo.App/MainWindow.xaml.cs:79-80,309`), and movie selection materializes an entire folder through `GetFullCategoryChannelsForAsync` → `GetAllChannels` (`src/Tvivo.App/MainWindow.xaml.cs:1987-2005`; `src/Tvivo.App/Pages/CatalogLandingPage.xaml.cs:302-312`; `src/Tvivo.Infrastructure/SqliteCatalogRepository.cs:603-614`). It also uses those full rows as the next/shuffle playlist (`MainWindow.xaml.cs:2528-2562`). Reusing that method for many folders would create 100k-row loads and change playback order when a category expands.

Recommended panel: a pinned, non-accordion “Now playing” row; beneath it, all provider **movie** or **series** folder headers collapsed initially, in provider order. Enter/Space/click expands one folder and collapses the previous one; activating the open header collapses it. Only the open folder owns item rows, with an explicit loading/empty/error row and a page continuation. Each header and item row is at least 44 DIP high; text wraps to two lines, never truncating ambiguous category names. Up/Down moves through visible rows, Right expands, Left collapses/returns, Enter activates, Escape returns focus to the playlist toggle. Focus follows the newly opened header and then its first item; when collapsing or changing category, restore focus to a visible header. Announce “expanded/collapsed, N items” through automation without chattering on page append. No hover-only operation is required.

For movies, activating an item uses the existing `PlayRelatedChannel` route (`src/Tvivo.App/MainWindow.xaml.cs:5360-5429`). For series, activating a series row opens that series' season/episode list in the same sidebar using `OpenSeriesAsync`/`ConfigureSeasonSelector`/`OpenSeriesEpisode` (`:2018-2119,2324-2376`); provide a 44-DIP “Back to categories” control that restores the selected series row and expanded folder. Keep live playlist behavior as it is. Preserve the current episode list and next-episode actions when merely browsing categories; do not reset playback state until the user selects a new item. Keep the actual next/shuffle queue independent of rendered page rows; define its scope as the currently playing item's folder and fetch successor IDs on demand or through a bounded queue, not by loading all folders.

Reuse `SqliteCatalogRepository.GetCategoryShelfDescriptors(account,type)` for folder ID/name/count (`src/Tvivo.Infrastructure/SqliteCatalogRepository.cs:494-525`) and `GetChannels(account,connection,type,groupId,offset,limit)` for a page (`:550-579`). Add a small `CatalogLandingPage` facade or dedicated player browser service instead of calling `GetFullCategoryChannelsForAsync` (`src/Tvivo.App/Pages/CatalogLandingPage.xaml.cs:269-312`). Use the same account-scoped resolved URI construction already used by `GetChannels`. Add a pure `PlayerCategoryAccordionState` in Core with `{contentType, expandedCategoryId?, selectedItemId?, pageGeneration, viewMode}`; its `Toggle` guarantees one open category, and stale page results are discarded after category/account/player changes. UI uses a virtualizing list of headers and current-page items in `MainWindow.xaml:768-844` plus `MainWindow.xaml.cs:2528-2562,5360-5432`. Load 50–100 rows per request, append only near the end, and keep at most about three pages plus folder descriptors in memory. Drop item view models and pending image loads on collapse, type switch, or exit; retain IDs/counts only. Avoid per-item artwork in the accordion unless it is already bounded by the existing artwork cache.

**Slice/tier:** Sol high: (1) pure state and tests, (2) paged repository/facade and tests, (3) virtualized XAML/focus, (4) selection integration and queue separation. **Tests:** Core transitions (same header collapse, cross-category single expansion, stale result, type/account reset, focus target); SQLite 100k-row fixture proving LIMIT/OFFSET and deterministic order; UI automation/manual D-pad and pointer for movie, series, empty folder, rapid toggle, back navigation, and no 100k-row allocation. **Risks:** existing full-folder playlist semantics, async stale updates, focus loss when rows are recycled, and series open's current assumption that its caller came from catalog. Do not open streams in automated tests.

## D. Spotlight long carousel — design only

### Reading of the proposal (six lines)

1. A page selects an ordered strip of roughly 70 Spotlight items, while showing only a viewport slice.
2. With no card focused, seven collapsed slivers fit in full and 0.3 of the next sliver peeks from the right.
3. Pointer hover, keyboard focus, or selection opens one card wide without changing the underlying item order.
4. The open card scrolls to the first full position at the left, with 0.15 of its predecessor still visible before it.
5. Three full collapsed cards follow the open card, then 0.15 of the next card peeks at the right.
6. Earlier cards remain offscreen to the left; users can move along the same ordered 70-item strip and back.

### Questions to ask her (recommended defaults and trade-offs)

| # | Question | Recommended default | One-line trade-off |
|---|---|---|---|
| 1 | Should pointer hover and keyboard focus open a card, with click/Enter playing it? | Yes; retain the current 350 ms hover dwell, focus opens immediately, click/Enter activates the open card. | Dwell prevents accidental opening, but adds a brief pointer pause. |
| 2 | Should movement scroll/animate, and what happens with reduced motion? | One short 180–220 ms horizontal ease; no flashing; instant reposition when system animations are off. | A short motion explains location, while instant mode avoids motion discomfort. |
| 3 | How should someone traverse 70 items? | Left/Right keys and visible edge buttons; wheel scroll horizontally over the strip; touch drag stays available. | Edge buttons add visible affordance but use some horizontal space. |
| 4 | Which 70 items belong on For You, Movies, and Series, and in what order? | Up to 70 per page; Movies/Series single type, For You alternating 35/35 when both have enough; stable order until the chosen rotation date. | Stable order helps return navigation but exposes fewer freshly added items mid-cycle. |
| 5 | Should Back from the player restore the exact Spotlight item and scroll position? | Yes, by stable item ID and offset, until the selection changes. | Restoration needs a little view state but prevents losing a place in a long strip. |
| 6 | At the first/last item, should missing peeks become blank gutters? | No; show the available neighbor, reclaim missing peek space for the open card, and disable the corresponding edge action. | End cards have slightly different open widths, but no dead blank area. |
| 7 | Are 7.3 idle and 0.15 side peeks fixed at all window widths and display scales? | Treat them as desktop targets; keep cards/controls at least 44 DIP and reduce the number of full slivers on narrow windows. | Responsive counts preserve legibility but differ from the exact desktop count. |
| 8 | Is a mix of duplicates or same-title editions acceptable among 70? | Keep current normalized-title/year deduplication and folder-source settings. | Deduplication may yield fewer than 70 when a source is small. |

### Layout and implementation sketch

Current `SpotlightSelector.SelectionSize=8`, candidate pool limit 200, and For You splits four/four (`src/Tvivo.Core/SpotlightPolicy.cs:110-171`); persisted selection validation also assumes eight (`src/Tvivo.Infrastructure/SpotlightSettingsStore.cs:111-145`). Rotation options are 1/3/7/10/14 days (`src/Tvivo.Core/SpotlightPolicy.cs:14,20`; `src/Tvivo.App/SpotlightSettingsService.cs:31-50`). The current strip opens index zero by default and makes open width depend on **all** selected items (`src/Tvivo.Core/SpotlightStripState.cs:4-23`; `src/Tvivo.App/Pages/CatalogLandingPage.xaml.cs:3086-3092,3123-3135`), which fails for 70. Replace that width rule with a viewport rule.

Let `V` be usable viewport width in DIP after edge controls, `G=8` DIP gap, and `C` the collapsed sliver width. Desktop idle has seven full cards plus 0.3 of card eight and seven gaps: `C=(V-7G)/7.3`. Clamp `C` to at least 44 DIP; if the viewport cannot support that, reduce the full-card count `n` and use `C=(V-nG)/(n+0.3)`. Hovered interior view has predecessor peek `0.15C`, open width `W`, three full collapsed cards `3C`, next peek `0.15C`, and five gaps: `W=V-(3.3C+5G)`. Compute the first visible offset from cumulative item widths so the opened item's left edge appears after the predecessor's final `0.15C` and one gap. If a side neighbor is missing, omit that peek/gap and give the released width to `W`. Set a reasonable open minimum (for example 300 DIP); when `W` would fall below it, reduce the number of following slivers rather than shrinking title text or targets. Preserve order by index; never move items in the collection merely to align the viewport.

Model pure state as `{itemCount, selectedId/index, openIndex?, firstVisibleOffset, inputMode}` in `SpotlightStripState`; transitions `Idle`, `HoverAfterDwell`, `Focus`, `Move(±1)`, `Activate`, `ReturnFromPlayer`, `Resize` should return both widths and scroll target. Add tests for 0/1/7/8/70 items, exact peek fractions and gap sums, interior/boundary selection, stable order, focus/hover behavior, resize and reduced motion (`tests/Tvivo.Core.Tests/SpotlightStripStateTests.cs`, `SpotlightSelectorTests.cs`). Keep stable IDs in daily selection storage, extend limits and schema validation without discarding old eight-item snapshots. Update `CatalogLandingPage.xaml:436-481` and `.xaml.cs:3070-3216,3247-3403`. Its `ItemsControl` with horizontal `ItemsStackPanel` should not be assumed to recycle 70 containers; use a verified virtualizing horizontal control or an explicit recycled window. The existing artwork window already targets visible indices plus one on each side (`CatalogLandingPage.xaml.cs:3406-3436`) and decodes Spotlight images at about `190×285` physical pixels scaled by display scale (`:4074-4075`). Retain only visible + one neighbor per side: at most about 10–11 decoded idle images, fewer while expanded. Cancel and release image work outside that window, keep 70 lightweight IDs/metadata, and measure memory, first paint, scroll smoothness, and 200% DPI before approval. No source implementation in this round.

**Slice/tier:** Sol high after questions: selector/storage migration; pure layout state; virtualized UI/artwork; accessibility/performance validation. **Risks:** existing whole-strip width animation on 70 items (`CatalogLandingPage.xaml.cs:3123-3194`), expensive artwork decode and metadata lookup, scroll/focus drift after Back, and a tiny peek becoming a mistaken click target. Peeks are hints; navigation uses full-width 44-DIP controls.

## E. Sleep timer: compact menu, one late hint, quiet stop

The flyout currently uses full-word presets and separate choice/armed/custom panels (`src/Tvivo.App/MainWindow.xaml:693-750`). The policy triggers a two-minute warning and then Fading (`src/Tvivo.Core/SleepTimerPolicy.cs:42-47,89-115`). UI displays a status panel for the *entire* armed duration, a centered warning, compact warning actions, and a full-screen ended overlay (`src/Tvivo.App/MainWindow.xaml:267-334,513-533`; `src/Tvivo.App/MainWindow.xaml.cs:4200-4309,4457-4511`). That explains the persistent warning and large stop message.

Use the same player flyout surface, brush, and 18-DIP row text as the other player menus, with 44-DIP minimum rows. Show one concise list: `15 min`, `30 min`, `45 min`, `1 h`, `1.5 h`, `2 h`, `End of this item` (hide for Live), `Off`; keep `Custom…` in a compact secondary view if 5–240 minute custom duration remains supported. Add 120 to presets; keep short visual labels but full spoken automation names. Armed state may show a single small remaining-time line in the flyout/tooltip, not a persistent screen badge. Mark the selected choice without changing its height. Remove the always-visible `SleepTimerStatusPanel`, centered `SleepTimerWarningPanel`, `CompactSleepTimerPanel` warning/end cards, and `SleepTimerEndedOverlay` from timer presentation. Do not replace them with toasts or repeated announcements.

In Core, replace the one-shot two-minute warning with a pure `ShouldShowHint(initialDuration, remaining)` policy: for duration at least 10 minutes, show only during the last five minutes; for shorter duration, only during the last one minute. Keep one small 18-DIP hint line near the player controls and an accessible but visually compact `Cancel` and `+15 min` action, each at least 44 × 44 DIP; no modal, no large text, no countdown announcement on every tick. Show the same hint in compact/mini mode without covering video or controls. Hide immediately on cancel/extend, and show at most once per armed deadline unless a new deadline later reaches its own hint window. `End of this item` has no predictable countdown; the flyout can state its mode, with no warning. At deadline, stop and save resume position using the existing generation-safe path (`MainWindow.xaml.cs:4457-4511`) and suppress next-item autoplay; leave the normal player shell/title visible with a standard 44-DIP Play again control or normal replay action, without an ended overlay. Re-enable an intentional manual replay only after resetting the ended timer state, so it cannot silently auto-restart. Keep a single polite accessibility announcement when the timer is set or actually stops, not repeated visible warning text.

Verify no timer hint intercepts navigation or hides the next-episode prompt.
