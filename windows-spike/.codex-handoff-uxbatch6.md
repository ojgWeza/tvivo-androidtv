# UX Batch 6 — fullscreen user findings

## VERDICT

Implemented the six source fixes and built the full WinUI solution. The build
reported 0 warnings and 0 errors. The app was not launched, so visual behavior,
playback, and process exit remain runtime gates.

## STRONGEST EVIDENCE

`dotnet build Tvivo.sln -p:Platform=x64 --no-restore -v:quiet` succeeded. The
captured build output is `D:\Temp\tvivo-uxbatch6-build.log`. `git diff --check`
found no whitespace errors in the edited source. The window controller remains
Win32-only for transitions and minimize: no `SetPresenter`,
`ExtendsContentIntoTitleBar`, or `SetTitleBar` call exists in these paths.

## PER-ITEM ROOT CAUSE AND CHANGE

1. **Fullscreen controls and process exit.** `ApplyWindowChromeState` collapsed
   `WindowChrome` whenever the window was fullscreen, leaving no in-content
   minimize, close, or windowed toggle. `MainWindow` never assigned its title.
   `OnClosed` stopped only the selected playback service and awaited cleanup from
   an `async void` event without a guaranteed process exit. The existing XAML
   chrome row now appears in fullscreen outside cinema; windowed mode uses its
   native title bar. The title is `Tvivo`. The row retains the disabled Compact
   button and Win32 minimize/window-mode actions. F11 is handled even if a child
   marked the key event handled. Close cancels current playback, stops both
   services, disposes both engines and the catalog timer/artwork work, then
   explicitly exits the process after bounded cleanup.
2. **Artwork and placeholder.** Both fallback `ContentControl`s had a
   `ContentTemplate` but no `Content`, so the Tvivo template had no content to
   instantiate. The 54 px icon was small within a 190×250 card. Image callbacks
   searched for fallback by name from the Image's parent grid, which is fragile
   across template name scopes; recycled images only loaded on `Loaded`, not on
   changed card data. Both controls now have content and stretch the template;
   the mark is larger. The Image stays transparent until its current bitmap
   opens, the fallback is found among actual sibling visuals, and data-context
   changes restart a bounded request. A failed, stale, or timed-out request
   leaves the full-tile placeholder visible. Existing decode dimensions remain.
3. **Movie autostart and side list.** A catalog card called
   `StartPlaybackAsync` immediately after changing the Player from collapsed to
   visible; because the stop task can already be complete, the first media open
   could occur before a player layout pass. A side-list click occurs after the
   surface is laid out. The side-list click also passed `Array.Empty<Channel>()`
   into the same selection handler, which replaced its own item source with an
   empty array. Both paths now use the same handler and retained sibling set;
   first playback yields one dispatcher turn and forces Player layout before
   opening media. Startup exceptions are surfaced as `HostFailure` and a
   `Retry` action rather than disappearing from the fire-and-forget call.
   Spotlight now supplies the sibling set of its containing shelf too.
4. **Back and Home.** The Player XAML had no Back or Home control, and Escape
   only exited cinema. The Player now has visible Back and Home buttons outside
   cinema. Back and non-cinema Escape return to the captured prior page without
   reconstructing the catalog; Home opens Home. Leaving Player stops playback.
   The old navigation cleanup also set `_isCinemaMode = false` before calling
   `SetCinemaMode(false)`, which skipped layout and window restoration. That
   premature assignment is removed.
5. **Stray ESC badge.** No XAML or C# creates a button with `ESC` content. The
   only source of that label was the unconditional Escape `KeyboardAccelerator`
   attached to the root grid. WinUI documents that accelerator combinations are
   shown in tooltips by default. The accelerator is removed; handled-event-aware
   root key handling now exits cinema or goes Back. No ESC overlay is created.
6. **Spotlight rotation.** The Batch 5 source selected a stable Spotlight only
   during snapshot rendering and had no timer, as its handoff stated. An
   eight-second timer now advances among distinct cards in the rendered
   snapshot, without rebinding shelf item sources. It runs only while Catalog
   is active, skips an open shelf or non-content state, and stops on close.

## RULED OUT

- The side list did not lose items because of a repository query: its click
  handler explicitly supplied an empty related-channel set.
- The image URL was not unconditionally absent at the card layer: `ToCard`
  passes `Channel.LogoUri` through as `ArtworkUrl`. This build alone cannot
  determine whether a particular remote image responds successfully.
- Spotlight had no timer before this batch; a stable per-mode selection alone
  could not rotate while the same catalog snapshot remained onscreen.
- The ESC label was not an explicit app Button in the scanned source.

## UNCERTAINTY

The catalog-to-player layout race is a source-supported explanation for why a
first click differs from a later side-list click, but no runtime trace proves it
was the only cause of the reported failed start. The exact ESC tooltip placement
and cause also need visual confirmation. Build success cannot establish remote
artwork response, timer animation, keyboard routing through native video child
windows, Win32 fullscreen behavior, or absence of a lingering process after
close. The explicit exit makes cleanup bounded but means any disposal that
exceeds the deadline is terminated with the process.
