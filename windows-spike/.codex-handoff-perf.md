# WinUI performance and robustness pass — interrupted baseline

## VERDICT

Baseline work is partial; the performance pass is **not complete**. The app started and the initial S2–S7 driver run finished. S7 reported process exit in 236 ms. No source code was changed, no after run exists, and monkey/heavy-user sessions were not started.

## STRONGEST EVIDENCE

- S2 My Tvivo idle, five minutes: CPU averaged 0.09% per core; working set peaked at 257 MiB; private bytes peaked at 194 MiB; GPU utilization stayed at 0%.
- S3 Movies idle, five minutes: CPU averaged 0.49% per core with a 24.11% peak; working set peaked at 417 MiB; private bytes peaked at 332 MiB; UI ping peaked at 774 ms.
- S4 50 mode switches: private bytes peaked at 345 MiB and handles at 1,798, versus about 194 MiB and 1,478 handles at idle; threads peaked at 63 and later returned near 40.
- The initial debug output contains 173 generic first-chance CLR notices (`0xE0434352`) without managed type or throw frame.
- See `perf/REPORT.md` and the raw CSV/log folders under `perf/` for full boundaries.

## EXACT BOUNDARY

`perf/Measure-Tvivo.ps1` was added and ran a one-minute sample plus the initial S2–S7 scenarios. The first S5 attempt used PageDown/PageUp and is explicitly invalid as a verified scroll. A second S5 run using mouse-wheel input returned an artifact path (`perf/scroll-20260926-144400/`), but the shell stopped initializing immediately afterward with exit `0xC0000142`. Its output and final process state could not be inspected. No source files were modified; no page heap or gflags settings were added.

- The captured runs did not reproduce the historic 446-thread / 1.4 GiB saturation.
- S7 idle close reported process exit within 236 ms.
