# UX Batch 1 handoff

## Scope

Implemented source changes for plan items 1–3 in `windows-spike/src/Tvivo.App/Pages/CatalogLandingPage.xaml` and `CatalogLandingPage.xaml.cs`.

## Changes

1. **Catalog snapshot reuse:** Added an in-memory cache capped at 16 query snapshots. Its key includes account ID, mode, selected group, filter, category sort, and offset. Mode changes save and restore the per-mode shelf/group/filter/sort/page interaction state. A matching snapshot is applied immediately. SQLite remains the source used to construct cache misses and remains durable storage.
2. **Refresh policy:** Provider sync occurs on an uncached/empty initial load, explicit Retry, or when the account-wide refresh is at least 15 minutes old. `CatalogRefreshService` refreshes all three catalog types, so a successful sync marks every mode fresh. Cache entries and freshness marks are invalidated on refresh and old account identity changes. No content mutation API exists in this page; a future mutation caller must invalidate the affected account entries.
3. **Spotlight selection and artwork:** Replaced first-card selection with a per-mode candidate selected from a stable ID-ordered set using an app-session/date/account/mode seed. The choice remains stable on rerender, and the prior candidate is skipped when possible. Added a Spotlight image bound to the selected card URL.
4. **Artwork fallback:** Replaced title initials with one local XAML Tvivo placeholder template (gradient plus screen/film/play glyph and wordmark), reused in tiles and the wider Spotlight. Image-opened hides the fallback; image-failed restores it. No remote placeholder asset is used.

- The request explicitly required source-only work; no build, tests, or app launch were performed. XAML event hookup/visual-tree lookup and WinUI image loading still need verification in the separate verification pass.
