# UX Batch 5 — catalog performance

## VERDICT

Implemented bounded catalog shelf realization and artwork loading in the WinUI
catalog. The full solution builds. Runtime performance and visual acceptance
are unverified because this was a build-only pass; the app was not launched.

## STRONGEST EVIDENCE

- `dotnet build windows-spike/Tvivo.sln -p:Platform=x64 --no-restore -v:quiet`
  succeeded with 0 warnings and 0 errors. The final output is in
  `windows-spike/.codex-uxbatch5-build.log`.
- The outer shelf surface is now a viewport-bounded `ListView`, with its own
  scrolling and recycling, instead of all shelf grids inside a `ScrollViewer`/
  `ItemsControl`. Shelf previews remain limited to 12 cards; the opened category
  remains paged at 100 cards.
- Debug output reports the realized shelf count and the sum of preview cards
  as shelf containers load and unload. This is the runtime measurement hook;
  no realized count is claimed from the build.
- Card and Spotlight artwork use `BitmapImage` decode dimensions of 380x500
  (380x276 for live cards) and 600x336 respectively. At most six requests enter
  the image loading stage at once. Unloaded images cancel pending work and clear
  their source; an incomplete request expires after ten seconds.
- A matching snapshot is reused for page requests. Applying the same snapshot
  with the same open-shelf state skips Spotlight and shelf-surface rebinding.
  Mode changes reuse cached snapshot data while rebuilding only the small
  realized viewport. The loading ring is visible from the initial frame and
  during mode switching. The toolbar reserves 52 px of height, and the sort
  control retains its layout slot in an opened shelf.

## EXACT BOUNDARY

This batch changes `CatalogLandingPage.xaml`, `CatalogLandingPage.xaml.cs`, this
handoff, and a short catalog realization decision in `docs/decisions.md`. The
page source already contained substantial uncommitted Batch 1–4 and other work
before this batch; this handoff attributes only the changes above. No commit,
push, install, app launch, emulator session, playback, or test run occurred.

## RULED OUT

- There is no Spotlight rotation timer in `CatalogLandingPage`; Spotlight
  selection occurs only when applying a changed snapshot or open-shelf state.
  No timer callback can rebind shelves through this page.
- The prior 12-card preview bound each shelf but did not bound the number of
  shelf visual trees. The new outer list addresses that distinct cost.

## UNCERTAINTY

Build success proves C#/XAML compilation, not that WinUI recycles at the desired
rate on the target catalog or that a loading frame is painted during every fast
cache hit. Native image cache memory, network cancellation timing, scroll
position, focus, sort/filter behavior, and toolbar position need visual/runtime
observation. The debug realized-count hook has not been sampled. No standalone
windowing unit test was added because realization is owned by WinUI's `ListView`
layout rather than a new pure paging algorithm.
