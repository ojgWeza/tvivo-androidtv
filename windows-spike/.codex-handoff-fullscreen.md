# WinUI borderless fullscreen replacement

## VERDICT

Replaced fullscreen presenter switching in `WindowStateController` with Win32 style and monitor-bound changes. The controller's constructor, `Apply`, `Minimize`, `Mode`, and `WindowMode` API are unchanged for `MainWindow` and cinema callers. Startup still requests fullscreen after XAML construction and before activation. This is a build-verified implementation, not runtime acceptance.

## STRONGEST EVIDENCE

- The prior A/B handoff records `0xC0000374` in all six launches that called `AppWindow.SetPresenter(FullScreen)`, while all three launches that skipped it stayed responsive for at least 18 seconds. The stable arm still constructed `WindowStateController` and executed its `OverlappedPresenter.SetBorderAndTitleBar(true, false)` setup.
- The replacement contains no `AppWindow.SetPresenter` call. Entry captures `GetWindowPlacement`, `GetWindowRect`, and the current style; uses `MonitorFromWindow`/`GetMonitorInfo` to choose the current monitor; removes overlapped-window style bits, adds `WS_POPUP`, and calls `SetWindowPos(HWND_TOP, monitor bounds, SWP_FRAMECHANGED)`.
- Exit restores the saved style and placement, then the saved bounds for a normal window, or sends a frame change without resizing a previously maximized window. The initial hidden window is centered at 1280×800 DIPs, clamped to the work area, using `GetDpiForWindow`; all fullscreen/restore coordinates passed to Win32 are physical pixels.
- `dotnet build Tvivo.sln -p:Platform=x64 --no-restore` succeeded with 0 warnings and 0 errors. After the final DPI/initial-placement edit, `dotnet build src/Tvivo.App/Tvivo.App.csproj -p:Platform=x64 --no-restore` also succeeded with 0 warnings and 0 errors. Logs are `D:\Temp\tvivo-fullscreen-build.log` and `D:\Temp\tvivo-fullscreen-final-build.log`.

## EXACT BOUNDARY

Only `src/Tvivo.App/WindowStateController.cs` changes behavior. `App.OnLaunched` still calls `MainWindow.PrepareForActivation()` after the window is constructed and before `Activate()`. `MainWindow` still hides/restores Tvivo chrome from controller mode, and its cinema entry/exit still calls the same controller. Native caption-button hiding remains the existing one-time `OverlappedPresenter.SetBorderAndTitleBar(true, false)` call; no presenter is changed for windowed or fullscreen mode. `Minimize` now calls Win32 `ShowWindow(SW_MINIMIZE)`.

## RULED OUT

- The source no longer calls `AppWindow.SetPresenter(FullScreen)`, `AppWindow.SetPresenter(Overlapped)`, or `CompactOverlay` for these transitions.
- No playback start, stop, stream, or player-instance change was added.
- No app launch, install, deployment, UI test, or stream playback was performed in this gate.

## UNCERTAINTY

The build verifies managed syntax and WinUI compilation, not native runtime behavior. It does not establish that style changes avoid the heap fault, preserve focus and custom titlebar dragging, hide native buttons at every scale, restore snapped/maximized placement, or maintain uninterrupted playback. The prior A/B implicated the presenter transition as the detection boundary, not necessarily the original heap write.
