## Buildable slices and acceptance

Each slice is independently buildable and uses TV gating where UI differs. The owner-approved emulator/install rule still applies: finish the code and local checks, then obtain one approval for the combined `tvivo_tv34` run. Haiku uses the existing real account without clearing data; it must not open a real stream except the **single, short, explicitly approved** player-Back check in slice 1. Automated tests use policies/fixtures only and never open a provider stream.

1. **Player Back (9).** JVM: exit intent idempotence, popup/controls/PiP policy, STOP acknowledgement and next-start serialization with a fake handoff, resume refresh after late ACK. Haiku on `tvivo_tv34` with the real account: only after explicit run approval, open one short real stream; log Back key delivery/exit/ACK times, one press from visible/hidden controls and menu, return focus, reopen only after release. Check PiP separately within that approved run if the device supports it. If the stick does not deliver `KEYCODE_BACK`, capture its actual key event before altering mappings.
2. **Shelf focus and empties (5, 6, 10).** JVM: empty-shelf policy, visible shelf index mapping, row↔header↔previous-row transitions, stable ID restoration and unloaded-target fallback. Haiku: My Tvivo, Movies, Series, never-watched Live TV, Search groups and opened Live grid; use Up/Down/Left/Right/OK/Back repeatedly, verify no empty Last watched block, no skipped See all, no lost focus, and symmetric return to top.
3. **TV density (4).** JVM: pure TV sizing/breakpoint policy only if extracted; no tests mirroring dp constants. Haiku: screenshot at real `tvivo_tv34` 1080p and physical 55-inch stick when available; record `wm size`, `wm density`, app `screenWidthDp`, safe-area/overscan. Require two complete ordinary poster shelves on My Tvivo, no focus clipping, one-line ordinary shelf titles with ellipsis, channel logos still fitted, Arabic/category labels untruncated.
4. **First paint and loading (3, 2).** JVM: first-run vs loading classifier (including a first-empty fixture), last-good snapshot/structural-diff policy, search debounce cancellation and stale-result suppression. Haiku on `tvivo_tv34` with the real account: cold launch with saved catalog, switch tabs during refresh, offline/retry, return from detail; capture frames/timestamps and verify no three blank art tiles, cached cards at first shell paint, no empty-grid flash, stable scroll/focus, one structural swap on uncached load.
5. **Shell icon parity (1).** JVM: TV action order/availability/accessible names as a small pure policy; verify no phone/tablet action regression. Haiku: compare the WinUI header and Android TV screenshot, traverse every icon by D-pad, confirm focus label and spoken semantics, search IME escape, sort/refresh/theme/Settings placement and Back return. Keep all header targets reachable at 960×540 dp and with RTL strings.
6. **Page keys and action cleanup (8, 11).** JVM: key-to-jump mapping, held-key timing/clamps/loaded-item targeting, no media-key collision, and watched-action absence in detail/episode UI policy. Haiku: exercise Page/CH/Home-movement/End-movement via `adb input keyevent` on `tvivo_tv34`, then test only keys present on the stick; long-hold D-pad and paging in large Movies/Live grids, focus/scroll restore after detail, and confirm Mark watched is gone while Clear resume remains. No streams.

No owner question is required to start planning. The only runtime uncertainty is whether the physical remote delivers Back and optional page/channel keys as expected; slice 1 and slice 6 capture that evidence before committing to an OEM-specific mapping.
