# Android player slices — 2026-10-16

**Status:** planning only, against the uncommitted `android/finalize-parity` tree. No build, emulator, installation, stream, or source edit was made for this plan. Implement one slice at a time; the owner must approve any later emulator/device deployment. `docs/android-parity-audit-2026-10-16.md` slices 2–3 and `docs/android-production-plan.md` Phase 3 remain the broader release context.

## Locked contract and starting point

- Android 1.0 includes a sleep timer, persisted Dark/Light choice (Dark default, as in WinUI), screen-off and background playback on phone/tablet for movie, episode and Live audio at minimum, and a floating PiP mini player when using other phone apps. This supersedes the older PiP-only background recommendation and light-theme deferral. Basic playback cannot depend on a Plus entitlement; the precise boundary between two basic themes and Plus themes needs the owner's answer below.
- Keep **one** Media3 ExoPlayer and one active stream per playback session. A foreground `MediaSessionService` owns playback, timer, recovery and next-item handoff. `PlayerActivity` owns only `PlayerView`/surface, Compose controls, PiP and UI binding through a `MediaController`. Replacing the Activity-only ownership explicitly supersedes `docs/decisions.md`'s 2026-10-07 player-control-surface decision and its prevention rule. Compose never owns a player.
- A transition to another item must stop/release the old media connection before `prepare()` opens the new URL; use one serialized handoff, session generation tokens and a single save-position path. Preserve the current Activity's `DefaultExtractorsFactory` flags, resume behavior, direct `.mkv`/`.mp4`/`.ts` URLs, TV D-pad focus and no-seek rule for Live. Preserve a paused session only while the foreground-service lifecycle is justified; Back/explicit Stop tears down. Do not assume PiP exists on TV.
- Current source: `PlayerActivity.kt` creates ExoPlayer, treats every `STATE_ENDED` as completion and releases in `onStop()`; `PlayerOverlay.kt` has seek and basic track menus but no saved track choices, timer or prompt. The manifest has no media service or PiP; `app/build.gradle.kts` targets SDK 34 and has Media3 ExoPlayer/UI 1.4.1 but no Media3 session dependency. The shared policies for next, track and stall already exist.

## Manifest and platform contract at current targetSdk 34

- Add `android.permission.FOREGROUND_SERVICE` and `android.permission.FOREGROUND_SERVICE_MEDIA_PLAYBACK`; declare the playback service with `android:foregroundServiceType="mediaPlayback"`, `android:exported="true"` plus controller admission rules, and the `androidx.media3.session.MediaSessionService` action. Add `androidx.media3:media3-session` at the repo's Media3 version. Use a single media session and foreground media notification while playback is active. Android's [MediaSessionService guide](https://developer.android.com/media/media3/session/background-playback) and [Android 14 foreground-service rules](https://developer.android.com/about/versions/14/changes/fgs-types-required) are the implementation references.
- Declare `android.permission.POST_NOTIFICATIONS` for planned non-exempt notification surfaces and handle API 33+ denial gracefully. A correctly configured **media-session notification is exempt from the runtime notification permission**; do not block playback on denial. Confirm the final notification set and permission prompt policy in the release manifest review. See [Android notification permission](https://developer.android.com/develop/ui/compose/notifications/notification-permission).
- Declare `android:supportsPictureInPicture="true"` on `PlayerActivity` and required PiP configuration-change handling; check `FEATURE_PICTURE_IN_PICTURE` at runtime and limit the intended UI to phone/tablet. Android TV PiP support varies by device/API, so no TV acceptance criterion depends on it. See [Android PiP guidance](https://developer.android.com/develop/ui/views/picture-in-picture).
- Keep `INTERNET`/`ACCESS_NETWORK_STATE` and the existing cleartext network policy. If the service enables ExoPlayer's network wake mode, add `WAKE_LOCK` and test battery/teardown behavior. Recheck manifest and Play declarations when targetSdk is raised for submission.

## Owner answers still needed

1. **PiP entry:** Should leaving a playing video for another app enter PiP automatically (the existing shared default says “while playing”), with explicit Back/Stop ending playback, or only after tapping a mini-player control? Should a paused video remain in PiP?
2. **Basic themes vs Plus:** Is the persisted Dark/Light choice free for everyone, while Plus “themes” means extra palettes/customization? This plan assumes yes until the entitlement boundary is confirmed.
3. **Background timer warning:** When a timer reaches its two-minute warning while the phone is locked or another app is open, should notification actions be shown quietly (recommended), or should there be a more interruptive alert? The expiry itself will stop playback and release the stream either way.

## Evidence limits

The WinUI sleep-timer policy and `MainWindow.xaml.cs` define the contract, but `windows-spike/docs/test-results-sleep-timer-2026-10-15.md` reports both attempted UI runs blocked before S1 by Windows foreground focus. Its behavior has not been verified in that report. This plan also has no Android runtime evidence. Each implementation slice needs its own JVM result and the stated later owner-approved device observation before it is called shipped.
