3. **Rank 1, provider refusal/throttling:** one upstream problem fits both independent HTTP paths; 429 already gets three bounded `Retry-After` retries (20 s cap), while 403 fails immediately. Proof line: `event=net.request category=catalog action=get_series_info status=429` (or `get_series`/`403`), available only when `TVIVO_NET_LOG=1`; otherwise add `trace=… op=series-info|series-list status=429|403 attempt=…`. `max_connections` is an account stream property, not evidence of a catalog limit; the pacing gate spaces starts by 300 ms but does not hold a request until completion.
4. **Rank 2, app authentication race or transport:** cached-first startup exposes Series before background authentication populates the provider's connection map; clicking then throws `InvalidOperationException` even if the provider works elsewhere. Proof line to add: `trace=… op=series-info outcome=unauthenticated providerConnection=false`; today's `series.open.exit reason=info-failed exceptionType=InvalidOperationException` is suggestive only. DNS/IPv6/proxy failure or the 5 min `HttpClient` timeout (20 s series-open limit) would show `trace=… op=series-info outcome=timeout|dns|proxy exception=… elapsedMs=…`; `auth=expired|inactive|invalid` would establish account change. There is no separate catalog session token in this code.
5. **Rank 3, changed payload; rank 4, local DB:** `get_series` requires a JSON array, while `get_series_info` expects an `episodes` object with arrays; malformed JSON throws, but absent/wrong-shaped episodes silently yields zero and no saved episode fallback. Proof lines to add: `trace=… op=series-list outcome=protocol shape=object` / `trace=… op=series-info outcome=empty episodes=0`; for SQLite lock/schema/write use `trace=… op=refresh type=Series stage=save outcome=db sqliteCode=… schema=…` (current source declares schema 16; batch-3's schema-12 observation was historical and did not prove this MSI's DB state).
6. **Why sudden / lower ranks:** provider rate limits or account expiry can flip remotely; cached-first startup opens a timing window before authentication; a changed series payload can affect one show; automatic refresh failure flips in-memory backoff to 20 s, 60 s, then 1 h, while manual retry bypasses it. `CatalogRefreshTasks` removes completed tasks, so a permanently cached failed task is unsupported; an in-flight task can be shared, and stale saved rows remain on screen. Proof line to add: `trace=… op=refresh decision=deferred retryAt=…` versus `trace=… op=refresh task=new|joined outcome=…`; `event=catalog.cache.refresh.complete outcome=failure` alone cannot identify the cause ([CatalogRefreshPolicyStore.cs](../../Tvivo-windows/windows-spike/src/Tvivo.Infrastructure/CatalogRefreshPolicyStore.cs)).
