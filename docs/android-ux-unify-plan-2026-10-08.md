## 4. Focus, Back, and instrumentation contract

Keep `focusProperties { enter }` for entry from a rail/panel and explicit item-ID `requestFocus()` after Detail return. Never use `focusRestorer()`. A focused card's **whole shelf** (heading, See all and card) must be within the visible vertical viewport; `LandingScaffold`/`ShelfRow` should request bring-into-view for the whole row after vertical focus change, while retaining horizontal item-ID position. Do not use a focusable heading merely to force scrolling.

| Screen / focus origin | Up | Down | Left / Right | Back |
|---|---|---|---|---|
| TV shell top tab | No-op at top | First real content target: core card/hint, sort if no shelves, Search field, or Settings first action | Adjacent tab, RTL-mirrored | Non-Home → My Tvivo; My Tvivo → exit-confirm |
| My Tvivo shelf card/hint | Previous shelf; first → selected tab | Next shelf; **last → no-op with focus retained** | Cards; edge stays in row, or explicit See all via header action | Exit-confirm |
| Type landing shelf card/hint | Previous shelf; first → selected tab | Next shelf or sort; last category → no-op | Cards; leading edge → Categories panel, mirrored in RTL | Panel closes; otherwise My Tvivo |
| Landing sort/category action | Prior shelf | First ALL/category shelf; if none, no-op | Across sort options, Filter/Categories as present; no hidden target | My Tvivo |
| Categories panel | Previous row/filter | Next row; last → no-op | Toward content returns to active row; away edge no-op | Close panel, restore opener |
| Opened grid header/chips/filter | Shell/earlier control | First grid item or empty action; bottom no-op | Chips/actions in visual RTL order | Text clears → field closes → panel closes → landing |
| Opened grid card | Header from first row, previous grid row otherwise | Next grid row; final item → no-op | Adjacent card, leading edge → Categories; restore by item ID | Landing with originating shelf heading/control visible |
| Search field/chips/results | Top tab or previous row | Next focusable result; last → no-op | Clear/chips/cards, RTL mirrored | Query clears, then My Tvivo |
| Settings/actions and Subscription/Diagnostics | Prior action/top tab | Next action; last → no-op | Available tabs/actions only | Child → Settings; Settings → My Tvivo |
| Item Detail / Series Detail | Prior visible action or episode | Next visible action/episode; last → no-op | Existing action/episode neighbor | Opening tab and exact item ID |
| Exit-confirm | Dialog bounds | Dialog bounds | Safe choice first; explicit Exit reachable | Dismiss, stay in My Tvivo |
| Login / loading | Form's prior action or no-op | Form's next action or no-op | Move within visible form, RTL mirrored | Dismiss IME first; signed-in switch returns to My Tvivo; signed-out Login and loading remain in app |

The shell must route **only** a confirmed Back to `MainActivity`'s navigation reducer. A Down event may change focus or be consumed at a boundary; it must never invoke exit, route Back, or leave zero focus owners. Use `FocusRequester.Cancel` (or equivalent verified Compose boundary) only for the terminal direction, and ensure it works with LazyRow/LazyColumn disposal and a disappearing category. The exit dialog is the only place allowed to call `Activity.finish()`; stale `ShellNavigation.backFromTopLevel` null/exit semantics must become an explicit `ShowExitConfirmation` action.

Add a debug-only root focus monitor at `AppShell` that records route, key code, focused test tag/item ID, and focused-node count after each TV D-pad event/frame; assert exactly one attached focused node for a settled interactive screen (allow the documented one-frame transition/dialog handoff). No credential, provider address, or title in logs. Add an instrumented test that sends Down repeatedly from every last card/row, asserts route unchanged and one focused node, then sends Back separately and asserts the correct route/dialog. Compiling this test is a build gate; executing it requires owner-approved emulator deployment. If the exit reproduces without a Back event, attach the event trace and fix the focus boundary. If Back appears, isolate its source before changing routing.

## 6. Open questions and default decisions

1. **Down exit event:** no source path connects Down to finish. Default: do not invent a Back fix; capture key/route/focus trace in slice 1, then fix the proven path. The present source has a real missing terminal-focus contract even if it is not the sole cause.
2. **Empty Favourites on type landings:** static source predicts the heading and hint after load. Default: treat the owner report as real but unresolved; test settled versus loading state with the same account/profile. Keep core hints everywhere after catalog state is Loaded.
3. **Sort meaning:** no per-item/channel visit count exists. Default: “Most visited” applies to category shelves; opened lists use A–Z, visibly scoped. All four options remain available for Live category shelves.
4. **Virtual Refresh:** default is a clearly labeled **Refresh Live/Movies/Series library** action that forces that type, rather than a no-op “Up to date.”
5. **Persistence lifetime:** no established durable user preference store for catalog sort/filter was found.
